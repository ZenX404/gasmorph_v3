## Clarifications

### Session 2025-12-26

- Q: 签到券抵扣额度如何定义？ → A: 券抵扣 100% GAS 费
- Q: 券在有效期内可使用次数？ → A: 单次券仅 1 次；时间段券在有效期内无限次使用
- Q: 时间段券有效期何时开始？ → A: 发行后立即开始计时
- Q: 控制台重复发券的处理规则？ → A: 允许重复发放；单次券累加可用次数，时间段券累加有效时长
- Q: 每日签到的“日”如何划分？ → A: 以 Asia/Shanghai 自然日计算

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 公开控制台查看与控制补贴 (Priority: P1)

任何访客无需登录即可进入控制台，查看补贴运行状态、关键指标和补贴账户相关信息，并可直接调整补贴开关与参数。

**Why this priority**: 控制台是补贴系统的运营入口，必须先能被访问并提供关键信息与操作。

**Independent Test**: 无需钱包连接即可访问控制台，能看到补贴状态与指标，并完成一次补贴开关操作。

**Acceptance Scenarios**:

1. **Given** 访客打开控制台页面，**When** 页面加载完成，**Then** 可见补贴开关状态、仪表盘指标与补贴账户信息摘要。
2. **Given** 控制台对外开放操作，**When** 访客切换补贴开关，**Then** 状态更新并能在页面中得到反馈。
3. **Given** 访客在控制台填写接收地址与券类型，**When** 发放补贴券，**Then** 页面提示发放成功并可在记录中看到该发放。

---

### User Story 2 - 演示页体验补贴与签到券 (Priority: P2)

用户在演示页连接钱包后，只能体验补贴效果与交易路径，并完成每日签到获取可抵扣 Gas 费的券 NFT。

**Why this priority**: 演示页是对外展示补贴效果与新玩法的核心入口。

**Independent Test**: 在演示页完成一次签到并获得券 NFT，随后发起一次演示交易并看到券生效的提示。

**Acceptance Scenarios**:

1. **Given** 用户已连接钱包，**When** 进行每日签到，**Then** 获得一张可用的券 NFT 且显示在券列表中。
2. **Given** 用户持有可用券，**When** 发起一次演示交易，**Then** 页面显示 Gas 抵扣效果并记录交易明细。

---

### User Story 3 - 券 NFT 转赠 (Priority: P3)

用户可在演示页对已获得的券 NFT 进行转赠，输入接收地址并完成转移。

**Why this priority**: 转赠能力体现 NFT 的资产属性，是补贴玩法的重要演示点。

**Independent Test**: 选择一张券 NFT，输入接收地址并提交转赠，转赠完成后券归属发生变化。

**Acceptance Scenarios**:

1. **Given** 用户拥有可转赠的券 NFT，**When** 输入有效地址并确认转赠，**Then** 券归属变为接收地址且状态更新。

---

### Edge Cases

- 当控制台对外开放且允许操作时，如何避免误操作或连续切换带来的状态抖动？
- 当补贴账户余额不足或交易失败时，控制台与演示页如何提示？
- 当用户在同一天重复签到或券已过期时，系统如何提示与处理？
- 当转赠地址无效或为空时，如何提示并阻止提交？
- 当控制台发放券时地址无效或券类型不匹配时如何处理？
- 当同一地址多次发放券时，如何展示已累加的次数或时长？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供独立的演示页面与控制台页面，并确保演示页不暴露补贴参数设置入口。
- **FR-002**: 控制台页面 MUST 允许任何访客无需登录即可访问。
- **FR-003**: 控制台页面 MUST 展示补贴开关状态与关键运行指标（如补贴次数、节省的 Gas、成功率等）。
- **FR-004**: 控制台页面 MUST 提供补贴开关的控制入口，任何访客均可修改开关状态。
- **FR-005**: 控制台页面 MUST 展示补贴账户信息与交易明细，包含地址、余额变化与交易列表，但不展示任何敏感字段。
- **FR-006**: 演示页面 MUST 提供每日签到入口，并在成功签到后发放一张券 NFT。
- **FR-007**: 系统 MUST 限制同一钱包每日最多获得一张签到券。
- **FR-008**: 券 NFT MUST 支持以下类型：单次抵扣、时间段内全额抵扣（1 分钟、2 小时、7 天）。
- **FR-009**: 券 NFT MUST 具备可转赠能力，用户可输入接收地址完成转移。
- **FR-010**: 演示页面 MUST 展示用户持有的券列表、状态（可用/已用/已过期）与适用范围。
- **FR-011**: 当用户持有可用券时，演示交易 MUST 展示券对 Gas 抵扣的效果。
- **FR-012**: 券与补贴开关的叠加规则 MUST 清晰可见：当补贴开关开启且用户持券时，优先使用补贴；当补贴开关关闭时，券仍可生效。
- **FR-013**: 控制台页面 MUST 支持向指定地址发放指定类型的补贴券 NFT。
- **FR-014**: 券 NFT 在生效时 MUST 抵扣 100% 的 Gas 费用。
- **FR-015**: 单次券 MUST 仅允许使用 1 次；时间段券 MUST 在有效期内支持多次使用。
- **FR-016**: 时间段券的有效期 MUST 从发放时刻开始计时。
- **FR-017**: 当控制台对同一地址重复发放券时，单次券 MUST 累加可用次数，时间段券 MUST 累加有效时长。
- **FR-018**: 每日签到的日期边界 MUST 以 Asia/Shanghai 自然日计算。

### Key Entities *(include if feature involves data)*

- **控制台配置**: 补贴开关状态、可调整参数的集合、最后更新时间。
- **补贴账户摘要**: 账户地址、余额变化、交易明细摘要、异常标记。
- **补贴交易记录**: 时间、发起方、交易状态、Gas 抵扣结果、券使用情况。
- **券 NFT**: 券类型、有效期、状态、持有人、转赠记录。
- **签到记录**: 钱包地址、签到日期、发放的券标识。

## Assumptions & Dependencies

- 假设演示页仅在钱包已连接时提供签到与券操作能力。
- 假设控制台展示的指标以“可理解的摘要”方式呈现，不暴露私钥或其他敏感凭据。
- 依赖补贴交易与券使用行为能被记录为可查询的交易明细。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 访客在 1 分钟内可进入控制台并查看到补贴状态与指标。
- **SC-002**: 连接钱包的用户在 2 分钟内完成签到并在列表中看到可用券。
- **SC-003**: 用户在 3 分钟内可完成一次券转赠并看到归属更新。
- **SC-004**: 90% 的演示交易能在页面中展示明确的补贴/券抵扣结果。
