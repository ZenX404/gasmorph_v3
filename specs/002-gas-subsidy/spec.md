# Feature Specification: Gas 补贴演示页面

**Feature Branch**: `001-gas-subsidy`  
**Created**: 2025-11-28  
**Status**: Draft  
**Input**: User description: "实现系统的核心功能：项目方可以为自己产品的用户补贴gas费。这个项目是想要参加黑客松比赛的，所以我们需要搭建一个演示页面，这个独立的页面用于直观的向平稳展示开启Gas补贴前后对比，所以这个页面要美观，能非常直观地展示出我们产品的核心功能。我们初步先开发核心地补贴功能就行，先把这个补贴Gas费操作地功能实现出来。这个演示页面可以先简单演示一个需要GAS费的操作，在关闭GAS补贴的时候，会需要用户授权支付gas费，开启补贴之后，用户就不需要支付gas费了。"

## Clarifications

### Session 2025-11-28

- Q: 补贴演示是纯模拟还是要跑真实链上交易？是否需要便捷切换环境？ → A: 开发测试阶段使用 Foundry 本地测试网；需支持一键切换到真实测试网（Sepolia/Monad）并上线演示，最终目标在真实测试网上运行。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 钱包连接与补贴开关体验 (Priority: P1)

访客打开演示页面，连接受支持的测试网钱包（Sepolia 或 Monad），阅读隐私提示与链 ID 说明，能切换“Gas 补贴”开关并看到状态变化。

**Why this priority**: 没有顺畅的连接与补贴开关体验，后续对比演示无法进行。

**Independent Test**: 仅通过连接钱包与切换开关，即可验证网络约束、隐私提示、补贴开关状态回显是否正确。

**Acceptance Scenarios**:

1. **Given** 用户使用受支持网络且未连接钱包，**When** 点击“连接钱包”，**Then** 钱包弹窗出现，确认后页面展示已连接地址与当前网络 ID，并出现补贴开关。
2. **Given** 用户在受支持网络已连接钱包，**When** 切换补贴开关，**Then** 页面状态与提示文案在 2 秒内更新为对应补贴开/关状态。

---

### User Story 2 - 补贴前后交易体验对比 (Priority: P1)

访客在同一页面发起示例需 Gas 的链上操作，能在关闭补贴时看到需自行支付 Gas 的流程，在开启补贴时看到项目方代付且无需本人支付的流程。

**Why this priority**: 补贴与非补贴的核心对比是产品价值的关键展示。

**Independent Test**: 不依赖其他故事，仅通过一次示例操作即可验证补贴开/关的差异及状态回执。

**Acceptance Scenarios**:

1. **Given** 补贴关闭且钱包已连接，**When** 用户点击“执行操作”，**Then** 钱包弹窗提示需支付 Gas，用户确认后页面展示交易结果与费用由用户承担。
2. **Given** 补贴开启且钱包已连接，**When** 用户点击“执行操作”，**Then** 操作完成后页面展示交易结果与费用由项目方补贴，用户不被扣除 Gas。

---

### User Story 3 - 费用对比与可视化展示 (Priority: P2)

访客完成任一操作后，能看到补贴前后 Gas 费用对比（数值与节省比例）及可视化组件，方便用于演示。

**Why this priority**: 量化的对比与可视化可以增强演示说服力，支持黑客松展示。

**Independent Test**: 通过一次操作生成的费用数据即可独立验证对比与可视化的正确呈现。

**Acceptance Scenarios**:

1. **Given** 至少完成一次操作，**When** 页面生成费用对比，**Then** 展示“未补贴费用”“已补贴费用”“节省比例”三项并数值一致、无负数。
2. **Given** 用户切换补贴开关再次操作，**When** 查看对比组件，**Then** 数据更新，且对比图表同步刷新，无陈旧数据。

## Edge Cases

- 钱包拒绝授权或关闭弹窗：操作中断，页面提示用户可重试，状态回滚。
- 切换到不支持网络（非 Sepolia/Monad）：禁止操作，提示“当前网络不受支持”，显示所需链 ID 并提供切换入口。
- 补贴额度不足或补贴服务不可用：回退为用户自付流程，明确提示费用承担方变化。
- 交易失败或超时：提示失败原因与重试建议，避免重复扣费。
- 在操作进行中切换补贴开关或网络：阻止中途切换，提示等待操作完成后再切换。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持钱包连接/断开，实时展示连接状态、地址与当前网络 ID。
- **FR-002**: 系统必须限制在 Sepolia 与 Monad 测试网运行；检测到其它链时必须阻断操作并提示切换。
- **FR-003**: 系统必须提供“Gas 补贴”开关，支持会话内记忆状态，并在 UI 中展示补贴开启/关闭的明确提示。
- **FR-004**: 系统必须提供至少一个示例链上操作流程；在补贴关闭时要求用户确认并自付 Gas，在补贴开启时展示由项目方代付的流程与结果。
- **FR-005**: 系统必须在每次操作后展示执行结果（成功/失败/取消）、交易标识或参考号、耗时与费用承担方。
- **FR-006**: 系统必须提供费用对比与节省比例的可视化展示，并确保数据随最新操作更新，无陈旧或负值。
- **FR-007**: 系统必须提供隐私与链 ID 提示，说明仅使用地址与链 ID，不收集额外个人隐私数据。
- **FR-008**: 系统必须处理异常：钱包拒绝、网络不支持、补贴额度不足或服务不可用时给出可行动提示与回退方案。
- **FR-009**: 系统必须支持环境切换：开发阶段可使用 Foundry 本地测试网验证完整流程，需一键切换到真实测试网（Sepolia/Monad）进行部署与演示，保证功能与回执行为一致。

### Key Entities

- **SubsidyConfig**: 补贴开关状态、适用网络、补贴额度/上限、补贴承担方说明。
- **OperationRecord**: 操作发起地址、网络 ID、是否补贴、预估与实际 Gas、交易标识/回执、结果状态、时间戳。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在受支持网络下，95% 用户可在 10 秒内完成钱包连接并看到补贴开关。
- **SC-002**: 补贴开关切换到效果回显的 UI 延迟不超过 2 秒。
- **SC-003**: 示例操作在补贴开启/关闭两种模式下的完成时间均不超过 10 秒，失败场景均有明确提示。
- **SC-004**: 费用对比组件在每次操作后刷新，显示“未补贴费用/已补贴费用/节省比例”，差异计算与展示准确率 100%。
